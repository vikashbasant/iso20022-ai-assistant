# ISO 20022 and pacs.008 for MT103 users

ISO 20022 is the XML-based messaging standard that replaces SWIFT MT messages for payments
("MX" messages). For cross-border payments on SWIFT, the usage rules are called CBPR+
(Cross-Border Payments and Reporting Plus). SWIFT's MT/MX coexistence period for cross-border
payment instructions ended in November 2025, so banks now send these payments as ISO 20022.

## Which MX message replaces which MT

| MT | ISO 20022 | Purpose |
|----|-----------|---------|
| MT103 | pacs.008 | Customer credit transfer (FI to FI) |
| MT202 | pacs.009 | Financial institution credit transfer |
| MT202COV | pacs.009 COV | Cover payment |
| MT199 / MT299 | free-format, or camt messages for exceptions | Queries and investigations |
| MT940 / MT950 | camt.053 | Account statement |
| MT900 / MT910 | camt.054 | Debit / credit notification |

## pacs.008 structure

- `GrpHdr` (group header): `MsgId`, `CreDtTm` (creation time), `NbOfTxs`, `SttlmInf/SttlmMtd`
  (for example `INDA` = settled through the instructed agent's account).
- `CdtTrfTxInf` (one per payment):
  - `PmtId`: `InstrId`, `EndToEndId` (the customer's reference, carried end to end), and
    `UETR` – a UUID that tracks the payment in SWIFT gpi. In MT103 the UETR is in block 3 field 121.
  - `IntrBkSttlmAmt` with a `Ccy` attribute, and `IntrBkSttlmDt` (settlement date).
  - `ChrgBr` (charge bearer).
  - `Dbtr`, `DbtrAcct`, `DbtrAgt` – the payer, their account and their bank.
  - `CdtrAgt`, `Cdtr`, `CdtrAcct` – the payee's bank, the payee and their account.
  - `RmtInf/Ustrd` – unstructured remittance information.

## Core MT103 to pacs.008 field mapping

| MT103 | pacs.008 |
|-------|----------|
| :20: Sender's Reference | `PmtId/InstrId` |
| Block 3 :121: UETR | `PmtId/UETR` |
| :32A: date | `IntrBkSttlmDt` (ISO date, e.g. 2026-10-30) |
| :32A: currency + amount | `IntrBkSttlmAmt Ccy="USD"` with a dot decimal, e.g. 1250.50 |
| :33B: | `InstdAmt` |
| :50a: | `Dbtr` (and `/account` line to `DbtrAcct`) |
| :52A: | `DbtrAgt/FinInstnId/BICFI` |
| :56A: | `IntrmyAgt1` |
| :57A: | `CdtrAgt/FinInstnId/BICFI` |
| :59a: | `Cdtr` (and `/account` line to `CdtrAcct`) |
| :70: | `RmtInf/Ustrd` |
| :71A: | `ChrgBr` |

## Charge codes

| MT103 :71A: | pacs.008 ChrgBr | Meaning |
|-------------|-----------------|---------|
| OUR | DEBT | Debtor (payer) bears all charges |
| BEN | CRED | Creditor (payee) bears all charges |
| SHA | SHAR | Charges are shared |

## Things that change compared with MT

- Decimal separator is a dot in XML, a comma in MT.
- Dates are full ISO dates (`YYYY-MM-DD`) instead of `YYMMDD`.
- Party data can be structured (street, town, country as separate elements) instead of 4 free
  text lines of 35 characters. CBPR+ is moving away from unstructured addresses, so translation
  of MT free-text addresses into structured ones is a common pain point.
- Fields are richer: ISO 20022 can carry the end-to-end reference, purpose codes and structured
  remittance data that MT103 cannot hold, so MT-to-MX translation can lose or truncate data.
